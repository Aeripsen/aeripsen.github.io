LedgerSentry

Fraud review is a budget before it is a model. Run fully automated, this catches 63 of the test fold's 75 frauds, 84%, at 29% precision on what it flags. Turn the review dial until 7.1% of transactions go to a human queue and precision on the flags reaches 89.8%, with misses cut from 12 to 6. The scores are calibrated, so a desk sets that dial from its own cost of a review against its cost of a miss, not from my defaults. The engine is FlowSentry's, pointed at the most used fraud dataset on earth, where the model cannot be the differentiator. The rigor is.

This is the table I would want handed to me if I ran the desk. Each step down in workload has its price in misses, each step up in precision has its price in queue depth, and none of it is extrapolated. Pick the row your team can staff.

The 0.99 row is the failure mode, printed rather than cropped: nearly the whole fold lands in the review queue, which is not a detector, it is a backlog. The weak spots section below names it.

Why an interval

Seventy five positives cannot earn four decimals.

The test fold has 56,961 transactions and 75 of them are fraud. Any metric computed on 75 events has a wide interval around it, and reporting 0.7278 without one invites a reader to believe the fourth decimal. Bootstrapping gives [0.6214, 0.8232], which is wide enough to change how you would read the result.

There is a second reason to publish it. A separate calibration run of this model scored 0.7544, and it would be easy to quote the bigger number as an improvement. It sits inside the interval, so it is not a demonstrated difference, and the repo says so about itself. The recall interval was cross checked a second way, with a closed form Wilson bound, and the two methods agree to about one point.

Do not mix these two

0.7278 is the shipped model, trained on the whole training fold. 0.7544 belongs to the calibration experiment, whose model was fitted on 80% so the rest could be held back to calibrate. Different runs, not a before and after.

The three decisions

  • Split by time, not by shuffle

    Fraud has patterns that move. A shuffled split trains on Tuesday and tests on Monday, which is a model scoring itself on the future it already saw. A time ordered holdout scores lower and is the only number worth quoting.

  • PR-AUC, and the proof that ROC-AUC would have flattered me

    At a 0.13% base rate, accuracy is a trap and ROC-AUC is close to one. So ADR 002 does not just argue it, it measures it on identical predictions: ROC-AUC 0.9740 against PR-AUC 0.7278, and accuracy 0.9971 against 0.9987 for always predicting legitimate. On accuracy, my model is measurably worse than doing nothing at all. Those keys ship nested under demoted_metrics with a why string attached, so a bare roc_auc can never get lifted out and used as a headline.

  • A calibrator chosen on a rule fixed before fitting

    The rule: the shipped calibrator must be strictly monotone, so it provably cannot damage ranking. That rule selects Platt. It cut test Brier from 0.00219 to 0.00052, a 4.2 times improvement, with PR-AUC unchanged at 0.754. Isotonic would have scored a marginally better Brier and cost PR-AUC 0.754 down to 0.673. Deciding the rule first is what stopped that from looking like a good trade.

Build and weak spots

FastAPI service, dashboard, GitHub Actions CI, 80 tests, six ADRs and a model card. make reproduce downloads the real public dataset, retrains, and fails if the committed metrics move by a byte. That has been checked from a cold clone against a fresh 284,807 row download.

  • The dataset is the most used fraud dataset in existence

    Anonymised PCA components from a European card issuer. Everyone has run it. If I cannot explain why a shuffled split leaks here, none of the above stands up, which is precisely why the split is the first thing the README talks about.

  • The reject knob degenerates at the high end

    Past threshold 0.95 the queue explodes: the 0.99 row in the table above sends all but 18 transactions to a human. Real, explainable, and printed in the table rather than cropped out of the curve.

  • The Docker image was never build tested

    The Dockerfile is committed and the README discloses that it has not been built in CI. Listing Docker on a project where the image was never built is the kind of small overstatement that costs an interview, so the repo says it first.
