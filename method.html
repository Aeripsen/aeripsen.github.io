How I run more parallel work than one person should be able to

On the research and the sites, I fan work out to a fleet of automated workers. That is not the interesting part, because anyone can start a lot of processes. The interesting part is the scaffolding that makes the output trustworthy: ownership rules so writes cannot collide, contracts that are checked by machine rather than self reported, and a verification layer whose default answer is no.

The framing

Treat a fleet of workers as a concurrent system, because that is what it is. It has the same three failure modes as any concurrent system: two writers touching the same state, a worker that reports success it did not achieve, and a result nobody can reproduce. Every rule below exists to close one of those.

The rules

  • One file per worker. No exceptions.

    Work is partitioned so two workers can never hold the same file. It is lock granularity chosen at the file level, and it means parallel edits merge trivially because they were never allowed to overlap in the first place. Getting this partition right is most of the design work, and it is done before anything starts.

  • Contracts with self tests a machine can run

    Every worker gets a written contract, and the contract's acceptance criteria are countable, not descriptive. On the charity site that means: bilingual span parity, every link and image source and element id preserved, a zero count against a list of forbidden phrases, and byte fidelity on blocks that are not allowed to change. A worker reports numbers. I read every diff before anything ships, and the numbers tell me where to look first.

  • A verification layer that defaults to refuting

    Findings do not get accepted, they get attacked. Each one goes to independent skeptics whose instruction is to refute it, and only what survives goes in. It is a council of judges rather than a reviewer, and it is deliberately biased toward rejection, because a reviewer that agrees with you is a rubber stamp with extra steps.

  • Route bulk work to the cheapest thing that can do it

    Extraction, translation drafting and other high volume mechanical work go through my own router to free tier models, in a fallback chain, so a recurring weekly workload costs effectively nothing. Judgment, wording, religious content and anything that touches production stay with me. That split is a cost decision made on purpose, not a limitation I ran into.

  • Guardrails as operational rules, not intentions

    Production deploys are gated on my explicit approval. One collaborator owned page is excluded from automation entirely and has to stay byte identical. Changeable facts are cite or cut, verified against the primary source with the date recorded, and Islamic calendar dates are checked against the organisation's own published sources every time.

  • A runbook written for someone less capable than the person who wrote it

    The weekly content routine is documented hard rules first, so it can be executed correctly by a weaker model or by a new volunteer with no context. If a process only works when I run it, it is not a process, it is a habit.

Proof

The reason I trust it is that it caught me.

The verification layer recounted my own data and came back with something I did not want: the numbers reproduce, but the mechanism you have written down is wrong. I had an explanation that fit the result and was not what the result actually showed. It did not ship. I corrected it first.

That is the whole argument for building this instead of just working faster. Speed is easy to buy. A system that contradicts its own owner, on his own data, before anyone outside sees it, is the part that is hard, and it is the part that made the FlowSentry benchmark publishable when the result went against my architecture.

Where it is running

This is in production today, not a proposal. It runs the weekly content operation on imammahdi.ca and the artifact verification behind every number on this site. The harness is Claude Code; the orchestration, the partitioning, the contracts and the guardrails are mine, and they would transfer to a different harness unchanged.

Applied here

Every figure on this site was read out of a committed artifact, and the artifact path sits under it in small type so you can go and check. Where a number would flatter me and is not supported, it is not on the page. Where a result went against me, it is on the page with the same weight as the ones that did not.

That is a policy, and it is cheap to state and expensive to keep. It is also the only reason any of the other numbers are worth reading.
